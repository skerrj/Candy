# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

"Candy" (`.cdy`) is an early-stage experimental language: statically typed, with an S-expression syntax, translated to Python by a translator written in Candy. `README.md` covers setup and use; `doc/process.md` covers how work is done (branches, commits and tags, design docs, where notes go). This machine's own setup (the Python environment, local checkouts) is in `CLAUDE.local.md`, which is not tracked.

The code:
- `src/cdy/` is the translator, in Candy: `cdyc.cdy` (its top file and driver) imports `form.cdy`, `read.cdy` (a hand-written reader), `syntax.cdy` (a special form's declared shape, and the check of a form against it), `include.cdy` (reads a program as modules), `expand.cdy` (macros), `core.cdy` (analysis into Core), `check.cdy` (the type checker, on Core), `lower.cdy` (the lowered IR) and `emit.cdy` (Python source), and the interpreter, `interp.cdy` (the evaluator, over Core) and `interp_builtins.cdy` (its built-ins). It also reads a library at run time, kept next to it: `special.cdy`, `system.cdy`, `translator.cdy`, `prelude.cdy`, `form.cdy` and `prelude_macros.cdy`, and the standard library's modules, `math.cdy`, `string.cdy`, `map.cdy`, `list.cdy`, `test.cdy` and `test_macros.cdy`. The special forms are declared in `special.cdy` and specified in `spec/` (the executable spec: `spec/README.md`, `doc/hl_rqmt/executable_spec.md`).
- `bin/` holds the checked-in translators, one directory per target: `bin/py/cdy_translator.py` is the translator translated by itself (generated; don't edit), with copies of the library files next to it. Rebuild it with `python src/py_cdy/self_host.py` after changing `src/cdy/`, or `test_self_host.py` fails; see `bin/README.md`.
- `src/cdy_rt/` is the runtime: `spelling.py` (each built-in's Python spelling and rendering kind, and an operator's function as a value; special forms have none) and `primitives.py` (the primitives generated code calls). It is the only package `pyproject.toml` packages.
- `src/py_cdy/` is the Python driver: `main.py` (translates a file to `output/<name>.py` with `bin`, or `--translator t1`; `--run` runs it, `--interpret` runs it on the interpreter instead) and `self_host.py` (builds T1 and T2, and rebuilds `bin`).
- `script/bootstrap.py` checks the bootstrap chain (`doc/hl_rqmt/bootstrap.md`); `script/doc_links.py` reads the docs' fences, ids and links; `script/backlog.py` reads the backlog and writes its index; `script/chat_archive.py` writes a branch's chat, from a Claude Code session's transcript, into `doc/archive/`.
- `backlog/` is the backlog (`doc/process.md`, "The backlog"; `doc/hl_rqmt/tracking.md`): one file per item, `B<n>-<slug>.md`, with a title, seven fields (kind, state, priority, found, fixed, where, refs), its text and, at the end, its dated `## Notes` (verdicts, caveats, why it was dropped or kept), and a generated index, `backlog/README.md` (rewrite it with `python script/backlog.py`; `tst/py_cdy/test_backlog.py` checks it is current). Kinds: `defect`, `leak`, `tech-debt`, `feature`, `task`, `idea`; states: `open`, `in-progress`, `review`, `done`, `dropped`, `kept`. A defect's `candy run`/`candy error` block is its repro, which `test_spec.py` runs as a strict expected failure. Ids are never reused.
- `editors/vscode-candy/` is a VS Code extension that highlights `.cdy` files (a TextMate grammar; install by symlinking, see its README; `tst/py_cdy/test_editor_grammar.py` checks it lists every special form).
- `spec/` is the language, rule by rule, each rule with examples that run (`spec/README.md`: the index of its files, and how to write one; `doc/hl_rqmt/executable_spec.md`). `tst/py_cdy/test_spec.py` runs every example through T1, one test each, named `file:line`: `candy run` blocks must print their `expect` block, pass `mypy --strict` (one mypy run per spec file) and translate the same under T2; `candy error` blocks and `candy errors` tables must fail with the given text, and `candy panic` blocks must translate and then panic, writing their `expect-panic` text. Examples print any value, as `show` writes it (`(List 1 2)`, `true`, `(Some 4)`; [[library.show]]). Every rule has an id, an anchor on the line before it (`<a id="match.exhaustive"></a>`), and other docs link to it, or to a backlog item, as `[[match.exhaustive]]` or `[[B12]]` (`tst/py_cdy/test_doc_links.py` checks every link, that every stable rule has an example, and that every built-in is in `library.builtins`' index and an example that runs). When the language changes, its spec file changes in the same step (`doc/process.md`, "The spec").
- `tst/cdy/` holds Candy programs with their expected output (`NAME.cdy` + `NAME.out`), in `tst/cdy/t1/`, `tst/cdy/` and `tst/cdy/cdyc/`; files they import live in subdirectories (`lib/`). Python tests are in `tst/py_cdy/` (whose `conftest.py` builds T1 and T2 once per session, for `test_self_host.py` and `test_spec.py`) and, for the runtime, `tst/cdy_rt/` (which import `cdy_rt.spelling` etc. through the editable install). `pyproject.toml` puts `src/py_cdy` and `script` on the import path for every tool (pytest, mypy, pyright, ruff, pylint), and holds tool config: line length 100 for ruff and pylint, `mypy --strict`, pylint exempts `test_*` functions from docstrings, and pytest deselects the `bootstrap` marker unless asked (`pytest -m bootstrap`).

Literals are `Int` `100`, `Long` `1500l`, `Float` `3.14f` (or `2.5e20f`), `Double` `10.0`, `Byte` `1b` (sizes: `Byte` 8 bits unsigned, `Int` 32, `Long` 64, a literal out of range an error; [[syntax.numbers]]), `Bool` `true`/`false`, `Char` `\e` and strings; they must end at a delimiter (whitespace, a paren, `;` or end of input). Quoting is the special forms `quo`, `quasi`, `unq` and `unq-sp`, for macros (`defmacro`; `doc/hl_rqmt/macros.md`). There is no `'` shorthand yet: `'` is reserved (a parse error) because the shorthand will come later as a Clojure-style reader macro.

## How the translator works

- **Modules** (`include.cdy`; `doc/hl_rqmt/namespaces.md`): `(import name)` at top level imports `name.cdy` from the importing file's directory, or else from the library (the translator's directory; a declaration module, one whose name prefixes `spelling.py`'s keys (`math.sin`), always from the library, and `(import system)` an error, since every file imports it); its top-level names become visible unqualified, and as `name.x` too ([[programs.qualified]]). `(import name (a b))` makes only `a` and `b` unqualified ([[programs.import]]); two imports that define one name are an error only where it is used unqualified, and a name an import leaves qualified-only gives way to a built-in (`(import string ())` leaves `len` the list's). `(private a b)` keeps a module's names from its importers ([[programs.private]]). What a file sees is one table, a name to an `Entry` (`core.cdy`); types, values and variants share it ([[programs.namespace]]), and a local shadows the file's own names, which shadow an import's, which shadow the built-ins and the prelude ([[programs.shadowing]]). Core keeps a name's module: a `Global`, a `TCon` and each definition carry the module that defines it and its name there (`system` for a built-in type, which every file sees as `system.name` too, [[programs.sees]]; `""` for macro code, *for now*: [[B197]]); the checker and `emit` key their tables by `global-key` (`util.greet`). Only `emit` spells a name in Python: prefixed with its module's file stem (`util__greet`), except in the top module (two top-level names that would be one Python name, such as `a-b` and `a_b`, or the top module's `util--greet` against that, are an error). So tests reach the translator's own internals by their Candy names, `candy(t1, "form.Sym")` (`test_self_host.py`, through `emit__py_global_name`). Macro files still use inclusion. Each module is analysed on its own, seeing what it imports (`core.cdy`), and all the modules' definitions are emitted as one Python file.
- **Macros** (`expand.cdy`): the translator compiles a program's `defmacro`s, and those of the macro files it loads with `import-macros`, runs them inside itself with the runtime's `load-macros`, and expands their calls. Every file gets `prelude_macros.cdy`'s macros (`cond`, and `put`, which writes its arguments' `text`s, a space between, with `put-line`).
- **The built-ins** (`doc/hl_rqmt/symbol_table.md`): `special.cdy` declares the special forms (`(special if)`, `import` with its shape: `(special import (ModName (Opt (List Name))))`, read by `syntax.cdy`); `system.cdy` gives every other built-in its type, the operators too (`(sig - (Fn (number number (Rest number)) number))`, with constraint variables and a rest parameter; `spelling.py` spells them infix, and gives each a Python function for when it is a value, `(fold + 0 xs)`), as a bodiless `sig` (like Carp's `register`, with no separate form), and a built-in's arity comes from its type; it also declares the built-in types, as bodiless `deft`s (`(deft (List a))`: a type's type variables give its number of arguments; `doc/hl_rqmt/name_checks.md`). The translator reads both into one map (`Builtin` in `core.cdy`, by `library-builtins` in `expand.cdy`) and checks it against `spelling.py` both ways (a type's spelling is a template, `tuple[{}, ...]`); `emit.cdy` reads `spelling.py`'s spellings as Candy data (`py-spellings`, a map of pairs).
- **The library** (`doc/hl_rqmt/library.md`, `doc/hl_rqmt/stdlib.md`): a host type's operations are built-ins, all of them, since lists (tuples), strings and maps are the host's, each collection's own, *for now* until interfaces ([[B34]]): the list's are `system.cdy`'s, every file's (`len`, `at`, `slice`, `map`, `filter`, `fold`, `map-acc`, `any`, `find-index`, `take`, `zip` and the rest), and a string's and a map's are their modules', which a program imports by convention with no names unqualified, `(import string ())`: `string.len`, `string.at` (a `Char`), `string.slice`, `string.split`, `string.join`, `string.trim`; `map.at`, `map.set`, `map.has`, `map.from`, `map.update`. A declaration module may hold Candy besides its bodiless `sig`s (`string.trim`, `math.abs`); `math` has `PI` and the trigonometry, `list` is Candy only (`list.sort`, `list.sum`), and `test` runs tests a program names (`(deftest name (check ...))`, `test_macros.cdy`; `(test.run (List t ...))` from `main`). Macro code imports `string` implicitly, qualified only; `text` is a value's text as `put` writes it (a string as itself, anything else as `show` writes it); `slurp` reads the path it is given, with no search, one it can't read a panic. Each built-in is specified in `spec/60-library.md`, with its type and what it does at the edges, `library.builtins`' table the index ([[library.builtins]]). `prelude.cdy` is a module every file imports implicitly, for what nearly every program builds on them: `rest`, `(deft (Maybe a) (Some ((v a))) (None))` with `find`, `index-of` and `with-default`, and `(deft (Result a e) (Ok ((v a))) (Err ((err e))))`. Macro code doesn't get the prelude (a leak); it has `form.cdy`'s `rest-of`. The translator's helpers for writing Python (`py-mangle`, `py-str`, `indent`, `PY_IMPORTS`) are ordinary Candy in `emit.cdy`, with no Python behind them; the built-ins only the translator needs are the five in `translator.cdy` (`py-spellings`, `load-macros`, `call-macro`, `module-dir`, `fresh-name`), a declaration module, which `(import translator)` always finds in the library: only a file that imports it sees them, and macro code imports it implicitly.
- **Self-hosting** (`self_host.py`): the checked-in `bin` builds T1 (`output/t1/cdy_translator.py`) from `src/cdy/cdyc.cdy`; `build_bin` has T1 build T2, checks T2 reproduces itself and passes `mypy --strict`, and replaces `bin` with it. `tst/py_cdy/test_self_host.py` runs every test program through T1 (output and `mypy --strict`) and checks the fixpoint: T2 passes `mypy --strict`, reproduces itself byte for byte, agrees with T1 on every program, and is `bin`.
- **Type checking** (`check.cdy`; `spec/25-checking.md`, `doc/hl_rqmt/type_checker.md`): after analysis and before `lower`, `type-check` checks the whole program, failing with the first type error ([[B134]]). It is unification with no let-polymorphism ([[B133]]): every top-level name has its `sig`, every built-in its `system.cdy` type, and locals' types are inferred; `Any` matches everything, both ways (gradual), and a variable that met only `Any` is `Any` at the end; a constraint variable (`number`, `integer`, `float`, `comparable`, `appendable`, `equatable`; `CONSTRAINTS` in `core.cdy`) takes only its constraint's types, `equatable` every type but one that is or holds a function, checked once the definition is (`check-compared`), and a `deft`'s type variable can't be one; a `(Tup ...)` isn't a `(List t)`, and `at` on one is an error (a tuple is taken apart by a pattern only); `nil` is only `Unit`'s, and an `if` with no `else` needs a `Unit` then; a call's `fn` arguments are checked after the others, so their parameters have types, and a `get` or `assoc` on a value of unknown type is a field constraint, solved once the definition is checked; a variant's constructor gives its sum, `get` on a sum names a field every variant has, and in a `match` clause on a local the local is narrowed to the clause's variant (a map in the checker's `Ctx`; `emit` reads the field on the match's temporary).
  - **Typed Core** (`doc/hl_rqmt/typed_core.md`): every Core `Expr` ends with a `pos` (leaves too; literal forms carry one, macro code writes `NOWHERE`) and then a `t`, its type: `analyse` writes `ANY`, and `type-check` returns the program with each node's type filled in (`retype-top` names each node's type `?eK`, the checker records what it finds, `typed`, and `node-type` puts in the final substitution). A type the checker never solved stays a `?N` type variable, which Python writes `Any` (*for now*: [[B132]]). `lower` keeps the types, and `emit` reads them for a nested `def` and a `let`-bound `lambda`. `TDef` and `TDefn` end with a `pos` too. Macro code is checked too, before it runs on the interpreter (since `host-macros`; [[macros.checked]]).
  - **Definition order** (`check-order`, after the type check): a `def`'s initial value and a top-level expression may use only names defined before them, through the bodies of the functions they call too ([[programs.def-order]]).
- **Errors** use the `fail` built-in, a panic (it raises `CandyFail`; a translated program first calls the runtime's `stop_on_panic`, so an uncaught one, or an `IndexError`, prints `candy: msg` and exits with 1, no traceback; [[library.errors]]), and say `file:line:col: msg`: every form carries a `Pos` (forms read from a `format` hole too, `read-hole`), and every Core node; `lower`'s and `emit`'s internal errors, which no program should reach, have none and say `internal error`.
- **The interpreter** (`interp.cdy`, `interp_builtins.cdy`; `doc/hl_rqmt/interpreter.md`): the second implementation. After the front end (read, expand, analyse, `type-check`), `interpret` runs the checked Core in place of `lower` and `emit` (`interpret-file`, `interpret-text` in `cdyc.cdy`; `cdy_translator.py --interpret FILE [ARGS]`). Its values are its own sum, `Value` (a size of number each, a `Long` or `Byte` holding an `Int` and a `Float` a `Double` as the literal forms do; a record or variant `VRec`, by module and name; a closure `VFn`; a constructor `VCtor`, a fieldless variant's too, since Core writes `Dot` as a call; a built-in `VPrim`), the locals by Core id, the globals by `global-key`. Every tail call runs as a loop (`eval-tail` and `apply`'s trampoline); other recursion goes only about 130 calls deep, the depth an implementation's ([[expr.tail-calls]]). `interp_builtins.cdy`'s table holds a function for each built-in a declaration module declares but `translator`'s (71; `nil`, `empty-list`, `map.empty` and `math.PI` are values), checked against them both ways on every run (`check-interp-builtins`): what the spec says beyond the host (`=`, the comparisons, `show` and `text` by the value, the bounds, the loops of those that take a function) is written there, the rest handed to the host's built-in of the same name. `test_spec.py`'s `test_interpret` and `test_interpret_panic`, and `test_self_host.py`'s `test_interpret_output`, run the spec and the test programs on it, in pytest's process.
- **`main`:** a program that defines `main`, typed `(Fn ((List String)) Int)`, runs it when its module is run (not imported), with the command-line arguments, exiting with its result (`run_main` in the runtime); `cdyc.cdy`'s `main` is the translator's driver.
- **Sum types** (`doc/hl_rqmt/sum_types.md`): `(deft Shape (Circle ((r Double))) (Rect ((w Double) (h Double))))`, taken apart with `(match s ((Circle r) ...) ((Rect w h) ...))` (exhaustive unless there is an `else`). In Python a variant is a `NamedTuple`, the sum a `type` alias of their union, and `match` an `isinstance` chain (mypy loses generic type arguments in class patterns) on a temporary typed `object` unless the sum is generic (narrowing a union of `NamedTuple`s makes mypy very slow); mypy narrows a generic one to `N[Any]`, so a clause's names are annotated, and a narrowed `get` of a type-variable field is cast (`_cdy_cast`), with the checker's type. Every class has `__eq__`, `__ne__` and `__hash__` that compare its class too, so `=` is by structure and class (`(A 1)` isn't `(B 1)`). A record's or variant's fields, and a `deft`'s type variables, must have different names (`core.cdy`); two fields can't be one Python name, and none can start with `_` in Python (`check-py-fields` in `emit.cdy`; `doc/hl_rqmt/field_checks.md`).

## Decisions that fill gaps in the spec

The translator is an **MVP path to bootstrapping Candy**: favour the simplest thing that works over completeness or performance, and expect parts to be replaced (`cond` is now a macro, and `defn` may become one).

- `let` bindings are `(name init)`: `(let ((x 1) (y 2)) (+ x y))`. They are sequential, like Scheme's `let*`: each `init` sees the names bound before it. Semantically `let` is an applied lambda, as in Scheme: analysis desugars it into nested applied `fn`s (Core has no `Let` node) and `lower` turns those back into plain assignments. `lower` also turns a top-level `defn` that calls itself in tail position into a loop, unless it makes a closure.
- `cond`'s `(else expr)` clause is optional (it is a macro, expanding into nested `if`s, the last with no `else`). An `if` with no `else`, and so a `cond`, is only for a `Unit` then, an effect, and gives `nil` (`None`) when the test is false (*for now*: [[B138]]). A missing value is a `(Maybe a)`'s `None`, a prelude variant, not `nil`.
- `def` must have an initial value: `(def x init)`. `def` and `deft` are only allowed at top level.
- `defn` and `fn` need at least one argument (`(defn f () ...)` is an error), and their body is exactly one form (use `do` for several). A function with no real input takes a `Unit` argument, as in ML: `(defn run (_) ...)`, called as `(run nil)`.
- Operators and built-ins (`+`, `*`, `=`, …) are not hard-coded in the translator: `system.cdy` declares them, and `spelling.py` maps each to Python (`spelling.py` and `primitives.py` started from smz's `table.py` and `smztils.py`, see below).
- smz ("schmuz") is a rough, untyped prototype of this same approach, already self-hosting (where it is: `CLAUDE.local.md`). Its Python version (`src/py_smz/`: `table.py` op table, `render.py` → Python source text) compiled its Scheme-syntax version (`src/smz/*.scm`), which then compiled itself. Use it as a reference, not as a style guide: it is imperative and untyped.
- Candy is **strongly and statically typed**. Types are declared in a separate **signature statement**, `(sig name Type)` (from Carp's `register`/`sig`): **required** for every top-level `def`/`defn`, allowed anywhere at top level before its definition, with `Any` as the escape hatch. The type names are `String`, `Unit` (value `nil`), `(Maybe a)` (the prelude's sum), `(Fn (Int) Int)`, `(List a)`, `(Tup a b)`, `(Map k v)`, `Any`, and lowercase type variables (iMVP doc, "Signature statement"). `(List a)` is a Python `tuple[A, ...]`; it will be one kind of abstract `Collection` (an interface, later). The translator checks that every type a program writes exists, with its number of arguments (`check-type`); the translator's type checker (`check.cdy`) checks the program against them, and they become Python annotations, which mypy checks as a second check ([[B125]]); a local `fn` (a nested Python `def`, or a `lambda` bound by `let`) is annotated with the type the checker inferred for it, a variable it never solved as `Any`.
- Candy literal types map to the simplest Python types: `Int`/`Long`/`Byte` → `int`, `Float`/`Double` → `float`, `Bool` → `bool`, `Char`/`String` → `str`. No `NewType`s: Python won't be the only target, so type distinctions belong to Candy's front end, not the Python backend. The layering is forms → Core (`core.cdy`) → the lowered IR (`lower.cdy`) → Python (`emit.cdy`); see "Layers" in the iMVP doc and `doc/hl_rqmt/multi_target.md` (future targets).
- Mutation (for example of `deft` records, which are immutable `NamedTuple`s) and optimizations are skipped for now; ideas go in `doc/hl_rqmt/mutation_optimization.md`.
- **Generated Python must depend only on the runtime** (`cdy_rt`: `spelling.py` and `primitives.py`), never on the translator or the driver. Keep those two modules self-contained: they import only the standard library. The runtime is installed editable in strict mode (see Running): strict mode links each file into `build/`, so edits show up immediately, but after **adding or removing a module** in `cdy_rt`, reinstall.
- `format` is hacked in, copying smz (an f-string with Candy forms in `{...}` holes). `Tup` builds a Python tuple; it is taken apart with a `Tup` pattern, in `match` or a `let` binding, which binds a temporary and reads each name with `at` (a stopgap, [[B17]]: the type checker checks the arity). Every such shortcut, and every place Python semantics leak into Candy, is a backlog item, a `leak` (or `tech-debt`, if a Candy user can't see it; something wrong by Candy's own rules is a `defect`): add one whenever a hack goes in. The lists before the backlog are archived in `doc/archive/` (`leaks_*.md`, `TODOS_*.md`), as history: each entry open when the backlog started is an item. Quick, undecided thoughts go in `doc/brainstorm.md`, and move to the backlog as an `idea` once written up. In an HLD, an answer taken as the simplest for the MVP says *for now* and links to the item that tracks it (`[[B12]]`); one meant to stay says *lasting*. The whole process is in `doc/process.md`.

## Python style

From the parsec.py v4 design notes (`doc/hl_rqmt/deps/parsec-py-DESIGN-COPY.md`), which the Python translator's parser was written against; the conventions still set the style for this repo's Python:

- **No decorators anywhere.** That includes `@dataclass`, `@property` and `@overload`. Use `typing.NamedTuple` for immutable records.
- **Pure functional style.** Results are immutable tuples.
- **Statically typed**, checked with mypy (strict) and pyright.

parsec v4 itself is needed only by the bootstrap chain's first step (the Python translator, at tag `self-host-py`); nothing on `master` imports it.

## Running

```
pip install -e . --config-settings editable_mode=strict   # (re)install cdy_rt, editable
python src/py_cdy/main.py FILE.cdy --run   # translate to output/FILE.py with bin, then run it
python src/py_cdy/main.py FILE.cdy --translator t1   # ... with T1, freshly built by bin
python bin/py/cdy_translator.py FILE.cdy [OUT.py]     # the checked-in translator on its own (default output/FILE.py)
python bin/py/cdy_translator.py --interpret FILE.cdy [ARG ...]   # run FILE on the interpreter
python src/py_cdy/main.py FILE.cdy --interpret   # ... the same, through main.py
python src/py_cdy/self_host.py             # rebuild bin/py/cdy_translator.py
python script/bootstrap.py --from-scratch  # the bootstrap chain, Python translator to bin (--check, --step C)

mypy src/py_cdy src/cdy_rt tst script   # type-check (both checkers currently clean)
pyright src tst script
ruff check src tst script               # lint
ruff format src tst script              # format
pylint src/py_cdy src/cdy_rt tst script
pytest                              # all tests (testpaths = tst)
pytest tst/py_cdy/test_main.py::test_out_path   # run a single test
pytest -m bootstrap                 # the bootstrap chain (deselected by default)
python script/backlog.py            # rewrite backlog/README.md after adding or changing an item
pytest tst/py_cdy/test_spec.py -k 30-match   # the spec, or one file of it
```

Run everything in the project's Python environment (Python 3.14; on this machine, see `CLAUDE.local.md`). `.gitignore` excludes `output/` and `tmp/`, so put generated artifacts there. `bin/` is tracked.
